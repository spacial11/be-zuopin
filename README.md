# ye队作品

**2026 第五届“未来杯”创新大赛 · 赛题一（Agent 编排创新应用）参赛作品**

队伍：ye队　作者：马君逸

一个可验证的多 Agent 编排原型。核心主张只有一句：

> **Agent 说“做完了”不算数，必须过两道独立的门才算数。**

第一道是确定性测试（跑得通），第二道是独立审查 Agent（是不是你要的那个东西）。
两道都过，任务才算完成；任何一道不过，自动进入下一轮修改。全过程落成可回放的事件流。

零第三方依赖，只用 Python 标准库。

## 为什么需要第二道门

单靠测试有一个死角：**测试全过，但做错了**。

原型内置的默认任务刻意演示了这个死角：

| 轮次 | 静态检查 | 确定性测试 | 独立审查 | 结果 |
|---|---|---|---|---|
| 1 | 通过 | 0/3 失败 | — | 驳回：测试未通过 |
| 2 | 通过 | **3/3 通过** | **驳回** | 驳回：任务要求支持小数，实现没有处理类型分支 |
| 3 | 通过 | 3/3 通过 | 通过 | 接受 |

第 2 轮是重点。如果只有测试，第 2 轮就会被判成功——这正是多数编排框架的问题。
审查 Agent 不跑代码，只对照任务契约读代码，专门抓“测不出来但确实错了”的情况。

## 它怎么跑

```
任务契约（JSON）
   ↓ 校验：函数名、测试用例、轮次上限、上下文预算、超时
规划：拆步骤、定验收标准
   ↓
有界调度器：按预算分配轮次，超预算就收口
   ↓
编码 Agent ──→ 静态检查（AST，白名单）
   │              ↓
   │           确定性测试（子进程隔离执行）
   │              ↓
   └────────── 独立审查 Agent（只读代码 + 契约）
                  ↓
            两道都过 → 接受
            任一不过 → 带着问题重来（最多 3 轮）
                  ↓
            结果缓存：同契约不重复跑
```

## 目录

| 文件 | 职责 |
|---|---|
| `contract.py` | 任务契约、Agent 注册表、规划器 |
| `runtime.py` | 上下文窗口、候选缓存、SQLite 事件存储、模型适配 |
| `engine.py` | 受限 AST 检查、子进程测试、审查 Agent、PDCA 循环、有界调度 |
| `predict.py` | 下一步意图预测：给可点的选项 + 统计命中率 |
| `inner.py` | 结构化决策记录：事实锁定由代码抽取，不由模型自述 |
| `web.py` | 浏览器面板：对话、主动插话、任务、事件流（SSE） |
| `__main__.py` | CLI：`demo` / `run` / `serve` |

## 跑起来

```bash
python -m tidal_harness demo           # 命令行走一遍三轮
python -m tidal_harness serve --demo   # 打开控制台 http://127.0.0.1:8765
```

打开后是一个控制台，主要区域：

| 区域 | 作用 |
|---|---|
| 开始页 | 白底 + 水流动画，选择「进入演示」或「用我的 API Key」 |
| 任务 | 一个输入框写任务，函数名与测试用例内置默认值 |
| 全自动 / 人工确认 | 全自动直接跑完；人工确认每次执行前先问一句 |
| 统计条 | 平均轮次、缓存命中、建议命中率、锁定事实数 |
| 思考链路 | 规划 → 生成 → 静态检查 → 测试 → 审查 → 裁决，逐节点显示通过或失败 |
| 逐轮回放 | 按轮次自动步进，高亮当前轮对应的节点 |
| 结构化决策记录 | 每轮的事实锁定、避开的开头、上下文用量 |
| 阶段事件 | 完整事件流水，逐条落库可回放 |

**用自己的模型**：开始页点「用我的 API Key」，填接口地址、Key、模型名即可，
后端会切换到真实模型；不填则使用内置演示模式。Key 只在本机内存使用，
写入数据库前会做脱敏。

## 三个可验证的设计

**1. 事实锁定不靠模型自觉**
从任务契约里用正则抽出数字与日期，作为不可变事实注入；
模型自述的“我记得是 3”不作为依据。代码在 `inner.py:facts_from_contract`。

**2. 上下文预算硬约束**
组装上下文时按 token 预算裁剪，放不下就整块丢弃，不切半块；
溢出直接报错，不做静默截断。代码在 `runtime.py:ContextWindow`。

**3. 失败也留证据**
每轮的代码、测试明细、审查意见都入库；失败不是黑箱，
可以回答“它到底卡在哪一轮、为什么”。

## 边界（如实写）

- 只支持**受限 Python 纯函数任务**：不允许 import、exec、文件与网络访问
- 上下文 token 数是工程估计，不是分词器结果
- 演示模式用脚本化输出；真实模型模式需配置 `TIDAL_MODEL_BASE` / `TIDAL_MODEL_KEY`
- 单样本运行数据不构成平均质量结论
- 审查 Agent 的判断力受模型能力限制，它不是形式化验证
